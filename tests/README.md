# Compact, private record and reconnect regression checks

Run `npm test` with Node.js 24 or newer. The checks evaluate the actual renderer and main-process modules in isolated VMs. Storage, Electron IPC, HTTP transports, SDK streams and retry timers are fixtures. Tests never use the application profile, call a live model, launch a routine or execute an agent command.

Coverage includes incremental summaries and retained turns across multiple compacts, model handoff and rollback, record visibility and lifecycle, password encryption with injected I/O failures, and retry behavior before and after response/tool activity across providers. Password checks use the actual PBKDF2/AES-GCM implementation.

ASK permissions are covered by `approval-permissions.cjs`: action-kind matching, exact shell/git requests, browser safety boundaries, per-chat persistence, reset, isolation from other chats and forks, encrypted storage and password rollback. These checks use only in-memory fixtures.

Run `npm run test:approvals-ui` for the Electron integration check of the three-button approval card and the chat-menu reset. It uses the real stylesheet, translations, card, deck, chat dispatch and storage code with fixture data. It tests both themes, four languages, narrow layouts, 200% zoom, keyboard access, reduced motion, persistence failures and reset failures. Screenshots and a JSON report go to a new temporary folder; the application profile is never opened.

Per-chat effort is covered by `chat-effort.cjs`: independent preferences for chats and drafts, unchanged last-picked-model defaults, legacy migration, persistence after restart, first send, model compatibility, request snapshots, quick-window settings rereads, routines, forks, protected mini chats and read-only slider updates. It runs actual modules with in-memory storage.

Run `npm run test:effort-ui` for the isolated Electron check of the real effort control while switching chats, changing models and reopening saved data. Its profile and screenshots also stay in a new temporary folder, not the application's profile.

Overload recovery is covered by `overload-retry.cjs`: the real OpenAI/ChatGPT stream parser, shared retry policy and `Chat.request` recover from known transient codes without an HTTP status. A narrow compatibility case recognizes the exact GPT overload message when both code and status are absent. The envelope type `error` is not a provider code. Structured failures from other remote providers use the same policy; local model failures, unknown errors, auth, credits/spend/quota and content refusals are not blindly retried. Tests also cover concurrent chats, existing tool-result history, unchanged request parameters, cancellation, usage accounting and one real-timer backoff.

Automatic mid-task continuation is covered by `auto-resume-transient.cjs`: actual Providers and Chat loop/request/queue handling retain partial visible text and completed tool outputs, discard incomplete calls/thinking, and open a new response part inside the same running turn. A trusted app note tells the model to continue rather than restart. Model, effort and session remain unchanged; pending recommendations are consumed at the normal queue boundary. Completed native reasoning blocks are preserved, conversations are isolated, and tool execution errors are never replayed by provider recovery. Direct DeepSeek reader failures retain their network classification after partial output; invalid JSON remains a protocol error.

Recovery uses one shared outage budget for the existing six waits (1, 2, 4, 8, 16 and 32 seconds), at most seven failed requests in a row. Only a successfully completed model response resets that budget. Before any activity the same request may safely replay; after content, reasoning or tool activity Chat sends a new request from retained progress instead. End cancels either wait immediately. Permanent/unknown errors and retry exhaustion retain the normal error and manual Retry. The transient overload and permanent billing codes follow the [OpenAI error-code guide](https://developers.openai.com/api/docs/guides/error-codes.md).

Run `npm run test:resume-ui` to boot the full real `desktop/main.js` and `index.html` against an isolated loopback HTTP/SSE server. The actual IPC, custom-provider parser, Providers, Chat, tools and storage run unchanged. The test server interrupts a response after a real read_file result and partial text/tool arguments; checks cover automatic completion, reconnection status, preserved history, no execution of incomplete calls, queued recommendations, End cancellation, permanent failures and bounded retry exhaustion. No live model, user profile or source-launch shortcut is used; reports and screenshots stay in a temporary folder.

Custom-provider error metadata is covered by `custom-error-metadata.cjs`: actual `desktop/local.js`, Providers and Chat retain symbolic codes/types and real HTTP or embedded stream statuses. Quota/billing/content refusals, explicit auth/request statuses and unknown stream failures stop after one request, including after visible partial text. Numeric status codes, flat/type-only envelopes, code/type precedence, bounded transient continuation, usage accounting and unchanged local HTTP500 behavior are checked. `test:resume-ui` additionally sends real HTTP429/quota and partial-stream permanent errors through the full application's socket/parser/IPC/storage path, and confirms that symbolic overload still recovers.

Native progress visuals are covered by `native-visuals.cjs`: actual `Chat.loop/request`, `StreamView` and Markdown preserve complete figures at tool-call boundaries without finishing the answer or changing stored model text. Checks include a closed fence without a trailing newline, incomplete fences, terminal-packet-only text, continued headings with stable colors, rich Markdown and native-output guidance assembled for six provider kinds in agent and plain-chat modes. Prompt assertions verify delivery of the guidance, not the behavior of a live model.

Run `npm run test:visuals-ui` for the real Electron renderer check. An isolated provider and paused fixture tool drive the actual chat loop and native diagram engine. It checks the figure before tool dispatch, continued SVG/view/heading identity, colored headings, tables and callouts, native editing, light/dark appearance, a narrow window, 200% zoom and reduced motion. Screenshots and the report stay in a new temporary folder. No live model, application profile, HTML preview server or agent command is used.

Draft photo preview is covered by `composer-photo-preview.cjs`: accessible thumbnail buttons open the existing viewer before sending, include only photos from that draft, preserve order/URLs/attachments and restore focus. Removal, invalid-image fallback, draft handoff and quick-viewer ownership are checked without a live application profile. Run `npm run test:photos-ui` for the real Attachments/PhotoViewer Electron check, including pending reads, keyboard navigation, captions/removal, floating composers, Escape isolation from agent stop, both appearances, narrow/zoomed layouts, reduced motion and decoding draft blob URLs in a separate photo window. Its report and screenshots stay in a new temporary folder.

Agent End is covered by `agent-end-button.cjs`: the real shared SendButton and main/mini/quick sync methods keep ordinary send, recommendation send and stop separate. An empty busy composer offers End; nonempty input still sends a recommendation. End delegates to actual `Chat.stop/abort`, including tool/approval cancellation, without dropping queued suggestions. It is disabled during cancellation, restores idle state afterward and uses the original 190/24 width spring. Its cached device-scale raster gives the stop square the same alpha rows as the actual E, preserves caption reveal/press feedback and the accessible text name, refreshes on resize/fonts/DPI changes, and retains the CSS fallback when a canvas is unavailable. Run `npm run test:end-ui` for actual shadow-button animation frames, native mouse/keyboard input, real send/stop bindings, all three composers, four languages, both appearances, narrow/200%-zoom layouts and reduced motion in an isolated Electron profile.

ASK reset visibility is covered by `ask-reset-visibility.cjs`: only ASK with saved grants for the selected unlocked chat offers Reset. Other modes, empty/locked/missing chats and read errors do not. Async menu reads are cancelled by closing or selecting another row. Run `npm run test:app-ui` to boot the actual `desktop/main.js` and `index.html` in a separate visible application window/profile, use the real mode picker and chat menu, reset real test-profile permissions and stop a real Chat turn. With `--all`, it also checks End against the supplied reference: coral red, semibold type, cap-height square sizing and actual cancellation in both light and dark application windows. Native captures require identical visible E/square top and bottom pixels at seven effective device scales (1, 1.25, 1.3125, 1.5, 1.8, 2 and 2.5), both themes and two window heights. Geometry is settled after zoom before taking the bitmap. A fresh dark-theme send-to-End transition additionally verifies white ink instead of caching the intermediate animated send color. Only provider replies are held locally; no live model or user profile is used. The test suppresses source-launch shortcut writing and keeps artifacts in a temporary folder.

Narrow browser tabs are covered by `browser-peek-tabs.cjs`: actual BrowserPanel tab creation, selection, blank/background tabs, close/trim behavior and the active-only CSS visibility exception. Run `npm run test:browser-ui` for the full real desktop application with two loopback pages and native clicks. The check covers a narrow overlay in both themes, independent new/blank tabs, switching/closing, address focus, widening into a docked panel and narrowing/reopening without showing an old page. The existing user profile, browser sessions and external sites are not used.

The file-tool privacy guard protects the application store, including saved copies of record tool calls, with case normalization and physical path resolution. It is a tool-level guard. The application's unrestricted shell still runs as the OS user; absolute isolation from arbitrary shell code requires an OS sandbox and is not provided by a path check.

These fixes keep existing on-disk formats. The preceding checkpoint commit preserves the reconnect changes that were uncommitted before this work. All audit fixes and these tests belong in the single following commit, which can be undone with `git revert <fix-commit>`.
