# Compact, private record and reconnect regression checks

Run `npm test` with Node.js 24 or newer. The checks evaluate the actual renderer and main-process modules in isolated VMs and loopback HTTP/SSE tests. Storage, Electron IPC, HTTP transports, SDK streams and retry timers are fixtures. Tests never use the application profile, call a live model, launch a routine or execute an agent command.

Coverage includes incremental summaries and retained turns across multiple compacts, model handoff and rollback, record visibility and lifecycle, password encryption with injected I/O failures, and retry behavior before and after response/tool activity across providers. Password checks use the actual PBKDF2/AES-GCM implementation.

ASK permissions are covered by `approval-permissions.cjs`: action-kind matching, exact shell/git requests, browser safety boundaries, per-chat persistence, reset, isolation from other chats and forks, encrypted storage and password rollback. These checks use only in-memory fixtures.

Run `npm run test:approvals-ui` for the Electron integration check of the three-button approval card and the chat-menu reset. It uses the real stylesheet, translations, card, deck, chat dispatch and storage code with fixture data. It tests both themes, four languages, narrow layouts, 200% zoom, keyboard access, reduced motion, persistence failures and reset failures. Screenshots and a JSON report go to a new temporary folder; the application profile is never opened.

OpenAI effort error recovery is covered by `openai-effort-errors.cjs`: the actual adapter runs against loopback HTTP/SSE. Rejected effort values, ambiguous errors, authentication/rate/server errors and an unsupported `reasoning.effort` are surfaced without a silent downgrade. The next request keeps its selected effort and encrypted-reasoning include; API and ChatGPT connections, other chats, concurrent models and catalogue levels cannot inherit a failure. Only structured unsupported-parameter errors permit request-local compatibility for the whole legacy `reasoning` parameter, optional summary or optional include. There is no cross-request model blacklist, and a selected effort is never removed on its own. Compatibility retries remove each rejected parameter at most once. No account or external service is used.

Run `npm run test:effort-errors-ui` for the full desktop client, actual adapter/IPC, native effort-control keyboard/mouse input and separate saved chats. In both appearances it verifies one visible Ultra error, a successful subsequent High, another chat’s Low, returning to High and reload persistence. Its default mode uses only loopback HTTP and a disposable profile. Optional `--live` requires explicit account authorization and an `OG_EFFORT_AUTH_HELPER` module that installs a read-only auth adapter; no credential is copied into the test profile, renderer or report. It checks short requests through two models from the accessible ChatGPT catalogue, including an actual unsupported-Ultra error followed by High and Medium, and captures request/response effort metadata without headers or tokens. Live mode is never part of `npm test` or the default UI command.

Fast speed is an independent, per-conversation opt-in, not an effort level. The existing Quick bolt appears to the left of the effort slider only after support is confirmed. New chats start at Standard; forks copy their source choice, minis store their own choice, and an active turn keeps its captured speed. Switching speed never lowers the chosen effort. Unsupported models and unresolved capability lookups have no bolt. The accessible hint warns about higher cost or allowance consumption; ChatGPT Fast currently consumes included allowance at 2.5 times the Standard rate.

Support follows the [OpenAI Fast guide](https://developers.openai.com/api/docs/guides/fast-mode) and the [ChatGPT speed guide](https://learn.chatgpt.com/docs/agent-configuration/speed): GPT catalogue `service_tiers` or `additional_speed_tiers` must explicitly advertise priority/Fast. Requests use `service_tier: priority`, or explicit `default` when turned off. Subscription requests also carry a model-scoped `x-codex-routing-hint` while retaining the OpenGhost client identity. A completed ChatGPT response can still report `service_tier: default`; that field alone does not verify end-to-end routing or actual speed. The live check verifies the selected request, routing hint, accepted effort and completion, not a latency or billing claim.

The [Claude Fast guide](https://platform.claude.com/docs/en/build-with-claude/fast-mode) documents Opus 5.5, 5 and 4.8. Because the Models API does not report this capability, only those exact version families and dated IDs are allowed. Opus 5/4.8 require `fast-mode-2026-02-01`; 5.5 does not. The 4.8 exception expires on 2026-11-30. Fast sends `speed: fast`; Standard omits it. Existing fallback beta headers remain intact. OpenRouter uses a lazy, deduplicated, account-scoped [model endpoint lookup](https://openrouter.ai/docs/api/api-reference/endpoints/list-all-endpoints-for-a-model), not the general catalogue's API-path `endpoints`. Only an available priority/Fast service-tier endpoint enables the bolt, following its [service-tier guide](https://openrouter.ai/docs/guides/features/service-tiers). Direct [DeepSeek](https://api-docs.deepseek.com/api/create-chat-completion), local and custom providers do not get an unconfirmed Fast option. Turning thinking off and the OpenRouter `:nitro` model variant are not treated as this mode.

Automatic mid-task continuation is covered by `auto-resume-transient.cjs`: actual Providers and Chat loop/request/queue handling retain partial visible text and completed tool outputs, discard incomplete calls/thinking, and open a new response part inside the same running turn. A trusted app note tells the model to continue rather than restart. Model, effort and session remain unchanged; pending recommendations are consumed at the normal queue boundary. Completed native reasoning blocks are preserved, conversations are isolated, and tool execution errors are never replayed by provider recovery. Direct DeepSeek reader failures retain their network classification after partial output; invalid JSON remains a protocol error.

Recovery uses one shared outage budget for the existing six waits (1, 2, 4, 8, 16 and 32 seconds), at most seven failed requests in a row. Only a successfully completed model response resets that budget. Before any activity the same request may safely replay; after content, reasoning or tool activity Chat sends a new request from retained progress instead. End cancels either wait immediately. Permanent/unknown errors and retry exhaustion retain the normal error and manual Retry. The transient overload and permanent billing codes follow the [OpenAI error-code guide](https://developers.openai.com/api/docs/guides/error-codes.md).

## Message dates and hover actions

`message-dates.cjs` is part of `npm test`. Message instants come from the user's computer and are saved as numeric `at` metadata, not added to message text. The whole message footer (clock and buttons) appears together on hover or keyboard focus and hides when it is left. Footers show only hours and minutes, without seconds or a repeated date. Calendar dates appear only in centered day separators, using the interface language and the computer's local calendar. Old ordinary messages without a saved instant remain undated; no date is guessed from chat activity. Existing exact routine timestamps remain usable. A queued user message keeps its send time, and forks and password-protected storage preserve the original metadata.

Run `npm run test:message-dates-ui` for the full desktop client in a disposable profile. Native pointer/keyboard checks cover hidden assistant/user actions, hover and keyboard reveal, left-aligned assistant buttons followed by the clock, and right-aligned user clock followed by the buttons, copying without dates, local midnight separators, queue persistence, real fork creation, independent split/mini timelines, narrow panes, password relock/unlock and reload. The test first verifies the real computer clock; its authored screenshot conversation then uses a fixture clock confined to that test process. Provider output and the clipboard sink are synthetic, so no live account or user clipboard is touched. Screenshots show idle and hovered messages in both themes. Day separators are presentation-only, do not enter provider history and are maintained by one child-list observer per conversation rather than a timer or streaming-text observer.

## Full post-1.5.2 audit

`npm run test:post152-ui` repeats all 20 interface suites serially, including the existing 16 regression suites. It removes `ELECTRON_RUN_AS_NODE` from child environments, retains stdout/stderr in a fresh temporary folder and verifies each child's saved JSON report. Native keyboard tests must not run in parallel. For shorter batches use `npm run test:post152-ui -- --block=1` (blocks 1 through 4, five suites each). Run `npm test` separately for the general module checks.

The four additional full-desktop suites also have individual commands:

- `npm run test:post152-visual-ui`: rich diagrams, tables, document and wireframe cards, both appearances, all ten real application scales from 80% through 300%, long model/mode labels, two mini windows, native divider/mini dragging and resizing, a live diagram editor, and native motion frames plus a WebM recording. Pixel comparisons verify that scrolled content does not obscure the right pane's caption. The caption uses an edge veil, not a mask on the scrolling pane: this preserves selection backdrop filtering and the sibling scrollbar's original fade. Transparent system backdrop pixels may encode black in the compositor video; native PNGs check the actual sidebar appearance separately.
- `npm run test:post152-background-ui`: actual loopback HTTP/SSE through the unmodified LLM IPC/parser and four real agent loops. Gated native write_file results must appear after closing a mini, selecting a third chat, automatic scale collapse, explicit split exit, opening the former right chat alone and rapid navigation. Two hidden mini agents then perform more real tools with the window minimized and no forced background-throttling override. Stopping one leaves the other running; a closed mini saves its final response and notification IPC reopens the correct existing mini. Shared-file coordination and release are checked too.
- `npm run test:post152-ownership-ui`: two actual browser webviews use the shared native keyboard queue, export separate screenshots and upload matching bytes to their own loopback forms. A running right chat moves to the main pane and back without recreating webviews, changing its turn, losing browser Take control/Hand back state or binding its globe to the other browser. Pending approvals remain conversation-scoped across third-chat navigation. An actual quick window and real claim IPC retain one writer while busy, release the completed conversation into split view and preserve its actual permission mode, not only its button caption.
- `npm run test:post152-storage-ui`: two actual fact keepers receive independent 40,000-character records, including early/middle/tail markers, and edit an early fact beyond the former 8,000-character tail. Oversize writes are rejected intact. Real password encryption covers messages, mini history, notes, draft, private record and permissions. Native password entry, relock, legacy records, pair restore/reload, protected mini context/mode/effort, private-path file-tool refusal and shared-memory exclusions are checked. Even a fixture keeper response that incorrectly returns a memory save cannot leak protected content into shared memory.

Every added suite boots the real desktop client with a disposable profile and workspace. Providers are synthetic or loopback only; no paid model, existing login, working profile, external message, installer or release is used. The background, ownership and storage suites request normal application shutdown; the visual fixture and pre-existing suites use a forced test-process exit. Child stderr is retained separately rather than hidden or counted as a renderer error. The old layout suite compares its known Electron bootstrap diagnostic against its baseline, and the scrollbar fixture separately records the known ResizeObserver diagnostic. A native Mojo widget message observed on forced exit is not proof of a runtime regression, but is retained as unresolved teardown/platform diagnostics rather than silently described as clean.

These changes preserve existing on-disk formats and are stored as local checkpoint commits on the audit branch. Each coherent checkpoint can be undone with `git revert <checkpoint>`; no merge, push, package build, install or working-client restart is part of this audit.
